Configure locale, labels, and reading direction

Set locale to choose localized digits and date labels. Register its Angular locale data so the picker can resolve regional week starts. Without an explicit input, locale comes from WKLY_CONFIG, then Angular's LOCALE_ID. The Gregorian adapter follows the effective locale; a supplied calendar adapter uses its own locale for calendar labels. The Arabic and Hebrew demonstrations also use right-to-left layout.

Angular example: localized controls

This catalog changes two controls; missing labels fall back to built-in English. The showcase supplies fuller Arabic and Hebrew catalogs. Locale data and control translations have separate jobs, so registering one does not supply the other. 

import { Component } from '@angular/core';
import { registerLocaleData } from '@angular/common';
import ar from '@angular/common/locales/ar';
import {
  WklyDateTimePickerModule, WklyPickerValue, WklyTranslations,
} from '@wkly/datetime-picker';

registerLocaleData(ar);

@Component({
  selector: 'app-localized-picker',
  standalone: true,
  imports: [WklyDateTimePickerModule],
  template: `
    <wkly-datetime-picker
      locale="ar" mode="datetime" [(value)]="value"
      hourCycle="locale" [weekOffset]="2"
      [translations]="translations">
    </wkly-datetime-picker>
  `,
})
export class LocalizedPickerComponent {
  value: WklyPickerValue = null;
  translations: WklyTranslations = {
    ar: { confirm: 'تأكيد', now: 'الآن' },
  };
}

Week starts, clocks, and stored values

Here [weekOffset]="2" means Saturday. WKLY offsets are measured from Thursday, so Monday is 4 and Sunday is 3. Omit the input to follow application or locale settings. hourCycle="locale" follows the locale's clock convention; h12, h24, and switchable override it. Manual fields accept recognized localized decimal digits.

The translations input replaces the injected WKLY_TRANSLATIONS catalog. Label lookup tries the full locale, broader language tags, then English. WKLY_LOCALIZATION supplies per-instance overrides ahead of that lookup. Changing display locale does not convert a stored value to another timezone: the selected value remains a canonical Gregorian UTC ISO string. A different calendar requires a calendar adapter, independently of translation.

See the locale and translation guide for application-wide configuration.
