Set colors and dimensions with CSS

The picker reads CSS custom properties from its host element. Set a few colors for a variation of the default theme, or also set surfaces, muted text, borders, errors, and focus colors for a dark interface. The examples above keep the same picker behavior while changing those values. Check text and focus visibility against your chosen backgrounds.

CSS example: a scoped inline picker

Add a class to one inline picker and put this rule in its host component's stylesheet. Import WklyDateTimePickerModule in that component or its NgModule. No theme package is needed. 

<wkly-datetime-picker class="booking-calendar" mode="date">
</wkly-datetime-picker>
wkly-datetime-picker.booking-calendar {
  --wkly-background-color: #ffffff;
  --wkly-text-color: #20243a;
  --wkly-accent-color: #5146a5;
  --wkly-accent-color-alternate: #dcd8f2;
  --wkly-accent-text-color: #ffffff;
  --wkly-range-color: #eeecf8;
  --wkly-size-multiplier: 1.15;
}

Dialogs, overlays, and available space

A dialog or CDK overlay creates its picker outside the trigger's DOM subtree. A class or CSS variable on that trigger will not theme the new picker. To style those presentations, place a wkly-datetime-picker { ... } rule in the application's global stylesheet. Keep the CDK overlay's structural stylesheet as well; picker color variables do not replace it.

--wkly-size-multiplier scales text within a 1–1.5 clamp. --wkly-size-unit, whose default is 3.5em, supplies base dimensions for controls and calendar cells. Day buttons fill their columns, so their width depends on the containing layout. Check touch targets on the devices you support after changing sizing. Larger text, longer translated labels, and more visible weeks can all require more room.

See inline and transient presentations for their setup, and the complete CSS custom property reference for the remaining tokens.
